# Конвейер агентной разработки onecdev

Опорный документ основного чата (**оркестратора**) и субагентов. Вход — `/pipeline` в Claude Code
или `$pipeline` в Codex. Протоколы ролей — `.claude/agents/*.md`, конфигурации Codex —
`.codex/agents/*.toml`; стандарт качества —
[vscode-extension-best-practices.md](./vscode-extension-best-practices.md); контракт архитектуры — корневой
[`CLAUDE.md`](../CLAUDE.md) (полные правила — [project-rules.md](./project-rules.md)); какие файлы трогать —
[change-recipes.md](./change-recipes.md).

## Цель

TDD с обязательными гейтом и ревью на каждой задаче — при расходе токенов, который позволяет вести много
задач в пределах лимита. Механическую работу (тесты, покрытие, lint, sanity) выполняет скрипт, первичное
ревью — внешний сервис на PR; LLM-агенты подключаются там, где без них теряется качество.

## Почему так устроено (замер расхода токенов)

Замер 2026-11-18 по транскриптам 13–18.11 (11 сессий, ~50 влитых задач, условный вес ≈ цена):

| Источник | Доля | Причина |
|---|---|---|
| Основной чат | 63% | В одной сессии вели до 24 задач подряд: медиана контекста 360 тыс. токенов, каждый ход заново оплачивает историю всех прежних задач. 77% его расхода — чтение кэша |
| `implementer` + `architect` | 29% | Архитектор и реализатор дважды изучали один и тот же код; `change-recipes.md` (62 КБ) читался целиком 9 раз |
| `reviewer` | 7% | 49 запусков, дёшево на запуск |
| Обвязка | ~8% | старт основного чата ~72 тыс. токенов; `CLAUDE.md` 43 КБ в каждом агенте |

Отсюда решения: **одна сессия — одна задача**; трек по умолчанию — **SOLO** без архитектора и реализатора
(план, тесты и код в одном контексте, код изучается один раз); первичное ревью — **CodeRabbit на PR**,
агент `reviewer` — только на FULL; рецепты разложены по файлам `recipes/`, `CLAUDE.md` сжат до краткого
контракта.

Предыдущий замер (сентябрь 2026, 118 запусков субагентов) привёл к объединению test-writer и developer в
`implementer` и к замене QA-агента скриптом `qa-gate.sh` — эти решения сохраняются.

## Правило сессии: одна задача

- Задача (issue) ведётся **в своей сессии** от создания ветки до merge PR. После merge сессия
  заканчивается; следующая задача — новая сессия (`/clear` или новая сессия приложения), а не продолжение.
- Вход — `/pipeline <N или описание>` в свежей сессии.
- Если пользователь в середине задачи приносит другую, её не начинают в этом контексте: заводят issue или
  предлагают отдельную сессию.
- Если контекст сессии приближается к ~250 тыс. токенов, а задача не закончена, — зафиксировать состояние
  (коммит WIP на ветке + краткая заметка «что осталось» в описании PR или issue) и продолжить в новой сессии.

## Роли

| Роль | Где | Модель | Когда |
|---|---|---|---|
| **Сессия задачи (оркестратор)** | основной чат | выбранная пользователем | всегда: триаж, ветка, на SOLO/FULL — план, тесты и код, гейт, PR, разбор замечаний, merge |
| **QA-гейт** | `.claude/scripts/qa-gate.sh` | — (скрипт) | всегда; тот же скрипт — в CI на PR |
| **CodeRabbit** | GitHub App, `.coderabbit.yaml` | внешний | всегда, на каждый PR в `main` |
| **reviewer** | `.claude/agents/reviewer.md` | sonnet | FULL — до PR; по запросу (`/review`) |
| **qa-e2e** | `.claude/agents/qa-e2e.md` | sonnet | только RED гейта с неочевидной причиной |
| **architect** | `.claude/agents/architect.md` | opus | только трек LARGE |
| **implementer** | `.claude/agents/implementer.md` | opus | только трек LARGE |
| **documenter** | `.claude/agents/documenter.md` | sonnet | только трек LARGE или `/document` |

## Триаж

- **SOLO** (по умолчанию): баг-фикс, доработка в рамках существующих контрактов, рефакторинг по рецепту,
  инструменты и документация — даже если затронуто несколько файлов.
- **FULL** — задача попадает хотя бы в один пункт:
  - добавляет тип метаданных / слот модуля (`ModuleSlot`) / дочерний тег (`ChildTag`) / схему свойств или
    меняет контракт `META_TYPES`, `MetaPathResolver`, `PropertySchema`, `TypedFieldPropertyRules`, ruleset
    формата (`infra/xml/format/`);
  - добавляет или меняет MCP-инструмент либо канон путей;
  - меняет контракт webview ↔ расширение (`src-ui/shared/protocol/`);
  - вводит новую подсистему или новый слой зависимостей между `domain/infra/ui/lsp/cli`.
- **LARGE** — FULL-задача, которая не помещается в одну сессию (новая подсистема, план на несколько
  этапов): план нужно сохранить вне контекста, а реализацию вести по частям.

Сомнение между SOLO и FULL решается в пользу FULL: его доплата — план, утверждённый пользователем, и один
запуск `reviewer`.

## Поток

```
/pipeline <задача> в НОВОЙ сессии
  │  ветка от origin/main (fix/… feat/… chore/…)
  │
  ├─ SOLO:  разведка (рецепт из recipes/, LSP, разделы docs) → тесты → код → compile + lint
  ├─ FULL:  план в plan mode (рецепт + best-practices, сигнатуры, план тестов) → утверждение пользователем
  │         → тесты → код → compile + lint → (после гейта) reviewer
  └─ LARGE: architect → план в docs/plans/<N>-<кратко>.md → implementer по этапам (свежий контекст на этап)
            → (после гейта) reviewer → documenter
  │
  ├─ qa-gate.sh  ──RED──→ очевидная причина: чинит сессия; неочевидная: qa-e2e по out/qa-gate.log
  ├─ документация — та же сессия, если изменился публичный контракт/поведение (LARGE — documenter)
  ├─ push ветки → PR в main (gh pr create) → CI (qa-gate) + CodeRabbit
  ├─ ожидание проверок в фоне: gh pr checks <PR> --watch (без опроса)
  ├─ замечания: .claude/scripts/pr-review-comments.sh <PR> → правки → push → повтор до «нечего чинить»
  └─ merge по подтверждению пользователя: gh pr merge --merge --delete-branch → сессия закончена
```

**Инвариант: QA-гейт и ревью — на любой задаче.** Ревью SOLO — CodeRabbit на PR; FULL и LARGE —
`reviewer` до PR и CodeRabbit на PR. Нерантайм-изменения (`.claude/**`, `docs/` без кода, `.github/**`)
гейт распознаёт сам: lint и sanity остаются, `npm test`/`coverage:changed` — `N/A`.

## TDD-петля

1. **Разведка — один раз и точечно.** Рецепт сценария — один файл `recipes/*.md` из индекса
   [change-recipes.md](./change-recipes.md); профильные `docs/` — разделами (`grep -n` по заголовкам, затем
   `Read` с `offset`/`limit`); потребители символов — `LSP` (`findReferences`, `incomingCalls`).
2. **План** (FULL — обязательно в plan mode, SOLO — по необходимости): критерии приёмки, файлы по рецепту,
   привязка к `META_TYPES`/`MetaPathResolver`, риски (BOM/EOL, post-mutation путь, границы слоёв),
   сигнатуры новых публичных функций, перечень тестов (фикстуры, ветки, параметризация).
3. **Контракт** — сигнатуры с заглушками, чтобы тесты компилировались и красный был на ассертах.
4. **Все тесты задачи за один проход** на реальных фикстурах (`example/2.20/src/cf`, `example/2.21/src/cf`,
   `example/2.21/src/cfe/EVOLC`) или реальных временных файлах; ветки для 100% покрытия изменённого —
   заранее.
5. **Красный** по правильной причине → **реализация** минимальным изменением → только связанные тесты
   (`npm run test:compile` → `MOCHA_GREP=… xvfb-run -a npm run test:fast`) → `compile` + `lint`.
6. **QA-гейт:** `bash .claude/scripts/qa-gate.sh` (база по умолчанию — `origin/main`; перед запуском
   `git fetch origin`) — запускать в фоне
   (`run_in_background`), уведомление придёт само. Внутри: lint, sanity-проверки,
   `COVERAGE_BASE_REF=<точка ответвления от базы> npm run coverage:changed` (полный `npm test` под c8 = регресс + 100% покрытия
   изменённого); если production-файлов для покрытия нет — обычный `npm test`. Сводка — в выводе, полный лог
   — `out/qa-gate.log`; коды и «перемерь, а не допиши тест» — [coverage-gate.md](./coverage-gate.md).
   Базовое состояние — 0 failing: любое падение — регрессия задачи. Флейк — дефект теста.

## Гигиена контекста (обязательна для сессии и агентов)

Основной расход — это размер контекста, умноженный на число ходов. Поэтому:

- **Не читать файлы целиком ради одного места:** `grep -n` → `Read` с `offset`/`limit`; символы — `LSP`.
- **Не перечитывать `CLAUDE.md`** — он уже в контексте. `docs/` — только нужный раздел.
- **Вывод команд — коротко:** `2>&1 | tail -40`; при падении тестов — `| grep -A15 failing`; полный лог
  mocha не печатать. Сводку гейта не дублировать чтением `out/qa-gate.log` без причины.
- **Ошибки компиляции — через LSP-диагностику**, `test:compile` — когда LSP чист.
- **Без разовых python/node-скриптов** для изучения XML или lcov.
- **Длинные прогоны — в фоне**, без опроса `sleep`/повторных `tail`.
- **Не повторять зелёный прогон «на стабильность».** Если за ~15 итераций тест не доводится до нужного
  красного/зелёного — остановиться и описать препятствие пользователю.
- **Субагентам — один бриф на задачу** (все тесты и ветки сразу), без пересказа `CLAUDE.md`.

## PR и ревью

- **PR в `main`** создаёт сессия после зелёного гейта: `git push -u origin <ветка>` →
  `gh pr create -R iljyxa/onecdev --base main` с заголовком «<что сделано> (#N)» и телом: что и зачем,
  сводка гейта, `Closes #N`. В заголовке и теле — никаких упоминаний Claude/ИИ.
- **CI** (`.github/workflows/qa-gate.yml`) запускает тот же `qa-gate.sh` с базой `origin/main`.
- **CodeRabbit** (`.coderabbit.yaml`) — первичное ревью каждого PR: русский язык, правила из `CLAUDE.md` и
  инструкции по путям. Он не заменяет гейт и не пишет код.
- **Ожидание:** `gh pr checks <PR> -R iljyxa/onecdev --watch` в фоне; по уведомлению —
  `bash .claude/scripts/pr-review-comments.sh <PR>`: компактный список **нерешённых** замечаний (файл, строка,
  суть, подсказка для агента) — без загрузки полного обсуждения PR.
- **Разбор замечаний** — как ревью от коллеги: проверить по коду, справедливое — исправить (с тестом, если
  меняется поведение), спорное — ответить в треде с обоснованием. Попутный дефект вне задачи — отдельное
  issue. После правок — гейт, push, повтор.
- **Merge** — только с явного подтверждения пользователя: `gh pr merge <PR> -R iljyxa/onecdev --merge
  --delete-branch --subject "Влить <ветка>: <что сделано> (#N)"` (merge-коммит = прежний `--no-ff`), затем
  локально `git switch main && git pull --ff-only` и удаление локальной ветки.

## Протокол `reviewer` (FULL, LARGE, `/review`)

Бриф ревьюеру: ТЗ и критерии приёмки, утверждённый план (или путь к нему), сводка гейта, база диффа. Код он
смотрит сам через `git diff`. Вердикт:

- **APPROVE** — соответствует ТЗ, рецепту, конвенциям, SOLID, best-practices; гейт GREEN.
- **RETURN** — список замечаний (файл:строка, что не так, чем чревато) с пометкой «реализация» или
  «архитектура» (утечка знаний из `META_TYPES`, нарушение границ слоёв, дублирующий реестр — архитектура,
  план пересматривается).

После доработки — снова гейт и `reviewer`.

## Трек LARGE: архитектор и реализатор

- `architect` записывает план **в файл** `docs/plans/<N>-<кратко>.md` (сигнатуры, этапы, тесты по этапам) и
  возвращает только путь и краткое резюме — план переживает смену сессий и не дублируется в контексте.
- `implementer` получает путь к плану и номер этапа, не повторяет разведку архитектора, кроме файлов своего
  этапа. Один этап — один запуск.
- После последнего этапа — гейт, `reviewer`, `documenter`: он актуализирует `docs/` и перечисляет протухшие
  комментарии в `src/**`; сессия правит их до завершения задачи.

## Окружение

**Песочница Bash и тестовые команды.** `npm test`/`npm run test:fast` и `qa-gate.sh` запускают
Electron-хост (`@vscode/test-electron`), который под стандартной песочницей Bash убивается сигналом. Эти
команды числятся в `sandbox.excludedCommands` проектного `.claude/settings.json` для Claude Code. В Codex
действуют разрешения выбранного окружения. Если Electron не стартует из-за ограничения песочницы, используй
штатный запрос разрешения для конкретной команды. Без дисплея гейт сам оборачивает прогон в `xvfb-run -a`.

**Фикстуры `example/`.** Каталог версионируется: это настоящая выгрузка платформы 1С (конфигурация
«Торговый учёт» на поддержке поставщика, форматы 2.20 и 2.21, расширение EVOLC), собранная скриптом
`example/tools/build-supported-cf.mjs` (порядок сборки и формат `ParentConfigurations.bin` — в шапке скрипта,
разбор формата — [architecture.md](./architecture.md#режим-поддержки-поставщика-parentconfigurationsbin)).
Если тесту не хватает объекта в фикстуре, конфигурацию дополняют и пересобирают выгрузку скриптом, XML
руками не правят. Ожидаемые значения берутся из фикстуры по имени объекта, а не по uuid. Отдельная фикстура
`example/support/changes-forbidden/ParentConfigurations.bin` (правила
`example/tools/support-rules-forbidden.json`) — конфигурация с флагом «изменения запрещены» для тестов
`SupportMode.Locked`.

**Обвязка сессии.** Старт основного чата включает схемы инструментов подключённых MCP-коннекторов и списки
скилов плагинов. Для работы над этим репозиторием лишние коннекторы (почта, календарь, документы) и плагины
стоит отключить в настройках приложения; проверка — `/context`.

## Границы

- Субагенты запускаются сессией задачи; друг друга не запускают.
- Права по ролям: `reviewer` — только чтение; `architect` — запись только в `docs/plans/`, `documenter` —
  только документация, `qa-e2e` — только тесты и E2E-фикстуры. Claude Code применяет хук ограничения путей
  для `architect` и `documenter`. В Codex границы задают инструкции, а оркестратор сверяет дифф по `AGENTS.md`.
- Ветки создаёт сессия задачи; коммиты — на русском, без упоминаний Claude/ИИ (см. `CLAUDE.md`).
