# Библиотека crs-api: что она знает о протоколе

Дата анализа: 2026-09-29.

[otymko/crs-api](https://github.com/otymko/crs-api) — библиотека на OneScript для работы с сервером
хранилища по http без запуска платформы. Изучалась как источник сведений о методах протокола, которых
нет в наших образцах трафика ([04-crs-protocol.md](04-crs-protocol.md)).

## Что это

- OneScript (`opm install crs-api`), MIT, около 40 звёзд. Последний коммит — 2021-05-13, проект не
  развивается.
- Писалась под платформу 8.3.12–8.3.15. Транспорт — только http (`POST` на адрес публикации `.1ccr`),
  tcp нет.
- Возможности: версия сервера, проверка существования хранилища, создание пустого хранилища,
  управление пользователями, список версий. Захвата, отпуска, статусов, помещения и получения нет.
- Тестовых данных почти нет: два XML-ответа, остальные тесты идут против живого сервера.

Как зависимость не подходит: нужна среда OneScript. Используется как справочник; код не
заимствуется (v8vscedit, из которого вырос onecdev, тоже не источник кода для crs —
[repository-crs.md](../../repository-crs.md)).

## Сведения о протоколе

Всё ниже относится к 8.3.x и подлежит проверке на 8.5.1 снятием реального обмена.

### История версий — `DevDepot_devDepotVersions`

Вызов с `crs:auth`, параметр — фильтр:

```xml
<crs:filter>
  <crs:mask value="0"/>
  <crs:beginDate value="0001-01-01T00:00:00"/>
  <crs:endDate value="0001-01-01T00:00:00"/>
  <crs:beginVerNum>4294967295</crs:beginVerNum>
  <crs:endVerNum>4294967295</crs:endVerNum>
  <crs:userIDs/>
  <crs:objRefs/>
  <crs:recursive value="false"/>
  <crs:labels value="true"/>
  <crs:onlyLabels value="false"/>
  <crs:configVersion value=""/>
  <crs:externals/>
  <crs:noExternals/>
</crs:filter>
```

`4294967295` (`0xFFFFFFFF`) — диапазон номеров без ограничения. `objRefs` с `recursive`, судя по
названиям, задают историю отдельных объектов; `userIDs` и даты — фильтры отчёта по хранилищу.

Ответ — `call_return` с массивом `versions`; у элемента `value/second/info`:

| Поле | Смысл |
|---|---|
| `versionID` | uuid версии |
| `verNum` | номер версии |
| `date` | дата помещения |
| `userID` | uuid автора |
| `code` | версия конфигурации (свойство «Версия») |
| `cvermajor`, `cverminor` | внутренняя версия конфигурации |
| `pvermajor`, `pverminor`, `pverbuild`, `pverrevis` | версия платформы, которой помещено |
| `comment` | комментарий |
| `file` | в crs-api описано как «данные конфигурации» |

Если `file` — содержимое конфигурации, оно не разбирается (запрет содержимого объектов,
[repository-crs.md](../../repository-crs.md)), а лимит размера ответа становится обязательным условием;
возможно, передачу данных отключает маска фильтра.

### Версия сервера

`DevDepotAdmin_openDevDepot` с `version="0.0.0.0"` и произвольным алиасом → `call_exception`, в тексте
которого версия сервера. crs-api вынимает её регуляркой
`(?:версия|version).*?([1-9]\.\d\.\d{1,3}\.\d{1,5})`. Годится для рукопожатия по версии: клиент узнаёт
версию сервера и повторяет вызов с ней.

### Исключения

`crs:call_exception` несёт атрибут `clsid` — идентификатор класса исключения — и base64 скобочного
текста (UTF-8 с BOM). `clsid` пригоден для классификации ошибок без разбора текста.

### Пользователи

| Метод | Назначение |
|---|---|
| `UserManager_addUser` | создание: `id`, `name`, `password` (хеш), `rights` |
| `UserManager_changeUser` | изменение имени, пароля, прав |
| `UserManager_removeUser` / `UserManager_resurrectUser` | деактивация и восстановление по `id` |
| `UserManager_depotUserByName` | поиск по имени |

Список пользователей, включая удалённых, приходит в ответе `DevDepot_devObjectsStatistic` с
параметрами `<crs:objRefs/>` и `<crs:removed value="true"/>`. Через него `userID` из истории и статусов
захвата переводится в имя.

Коды прав (`rights`):

| Код | Права |
|---|---|
| `1` | захват объектов |
| `5` | захват и изменение состава версий |
| `32773` | администратор |
| прочее | только просмотр |

### Совпадения с нашим разбором

- Хеш пароля — md5 от UTF-16LE без BOM, hex в нижнем регистре.
- Для http — тот же конверт `crs:call` (`http://v8.1c.ru/8.2/crs`, атрибуты `alias`, `name`,
  `version`).

Расхождение по `crs:bind`: в вызовах `UserManager_*` и `DevDepot_devObjectsStatistic` crs-api
передаёт `bindID` — случайный uuid на каждый вызов, а `DevDepot_devDepotVersions` и
`DevDepot_depotInfo` отправляет вовсе без `crs:bind`. Конфигуратор в наших образцах регистрирует
привязку в `DevDepot_bind` и дальше в сеансе использует тот же идентификатор. На 8.5.1 проверить,
принимает ли сервер случайный `bindID` и вызовы без `crs:bind`, в том числе историю (проверено, см.
«Проверка на 8.5.1» ниже: принимает).

## Проверка на 8.5.1

Снятие трафика истории ([06-crs-history.md](06-crs-history.md)) уточнило четыре пункта: Конфигуратор вызывает
`DevDepot_devDepotReport` (не `devDepotVersions`), «без ограничения» в фильтре — `-1`, а не `4294967295`;
поля `file` в ответе нет; коды прав на 8.5.1 другие (`65535`, `3`, `0`). Список пользователей, как и
сказано выше, приходит в `devObjectsStatistic` (и ещё в `UserManager_depotUsers`).

Пробы фильтров (2026-09-30, iljyxa/vscode-1c-repository-tools#39, раздел «Фильтры истории» в [06-crs-history.md](06-crs-history.md)):
`DevDepot_devDepotVersions` на 8.5.1 есть и отвечает `crs:versions`, как описано выше, но фильтр в записи
crs-api (числа текстом узла) сервер отвергает — «Ошибка преобразования данных XML»; с `-1` в атрибуте `value`
отвечает. `mask` — битовая маска включённых фильтров (`1` — номера и даты, `2` — `userIDs`, `4` — `objRefs`),
поэтому с `mask=0` из crs-api фильтры по авторам и объектам не действуют.

### Рукопожатие по версии и исключения (2026-09-30, iljyxa/vscode-1c-repository-tools#13)

Проверено пробами `example/crs/8.5.1/tcp-raw/probe-version-*` и `probe-wrong-alias` на `crserver` 8.5.1.1529
(запрос — снятый `openDevDepot`, меняются только `version` и `alias`).

| Проба | Отказ |
|---|---|
| `probe-version-zero` (`0.0.0.0`) | `call_exception`, clsid `3ccb2518-…`, код **17**; текст «Несоответствие версий клиентского приложения и сервера хранилища конфигурации. (Версия клиентского приложения:  0.0.0.0 / Версия сервера хранилища конфигурации: 8.5.1.1529)» |
| `probe-version-zero-wrong-alias` | тот же ответ: **версия проверяется раньше alias**, рукопожатие работает и на пустом `crserver` |
| `probe-version-other` (`8.3.27.2342`) | тот же отказ: версия нужна **точная**, версия чужой платформы не принимается |
| `probe-wrong-alias` (версия верна) | clsid `3ccb2518-…`, код **1**; «Хранилище конфигурации по адресу: crsdata/nosuch не обнаружено.» и вложенное «Отсутствует файл базы данных …» (clsid `f4e17562-…`); совпадает с `http/probe-wrong-alias` |

Уточнения к сведениям crs-api:

- Регулярное выражение crs-api по тексту находит версию **клиента** первой: в отказе версии клиента
  (`8.3.27.2342`) она стоит раньше версии сервера. Версия сервера — последнее совпадение; надёжнее опереться
  на пару clsid + код (17).
- `clsid` `3ccb2518-…` общий для неверного пароля (код **4**), отсутствующего хранилища (код 1) и
  несовпадения версий (код 17): вид отказа различает код — второй элемент корневого списка скобочного текста.
  Исключение разбора XML (`c593fe3b-…`, VRS, статус 400) — код -6 в данных.
- Форма корня исключения проверена на `crserver` 8.5.1 около тридцатью некорректными вызовами (iljyxa/vscode-1c-repository-tools#56):
  неверные и пропущенные параметры методов чтения и `bind`, чужая и пустая версия, пустой и длинный alias,
  `../..` в alias, неверный хеш пароля, неизвестные методы, методы без прав. Везде корень —
  `{ <запись>, <код>, {"file://crsdata/<alias>",0}, "<текст>" }`, а код — числовой атом (`-6`, 1, 3, 4, 10,
  11, 17). Вложенного списка или пустого значения на месте кода сервер не отдаёт, поэтому `Number(root[1])`
  в `decodeCallException` на настоящих ответах не ошибается, а ветка «код не атом» непокрываема артефактом
  (синтетика запрещена). Новые наблюдения: код 3 — «Ошибка соединения с хранилищем» (пустой alias и `../..`),
  код -6 с clsid `d5d3ce23-…` — «Ошибка преобразования данных XML» на неверные параметры метода (статус 200,
  в отличие от исключения VRS).
- В исключении о версии есть вложенная запись с пустым сообщением (`{9f06d311-…,"",…,"8.5.1.1529"}`),
  а в корне после кода — `{"file://crsdata/",0}` и повтор текста о версиях.
- Хеш пароля подтверждён на шести парах стенда (`Admin`, `Petrov`, `Sidorov`, `Reader`, неверный `Petrov`,
  несуществующий `Nobody`): md5 UTF-16LE, hex нижним регистром. Все шесть сверены по tcp; по http
  истории нет, там сверяется принадлежность снятых пар набору стенда.
- `crs:password` есть и в ответах (`devObjectsStatistic`, `depotUsers`): хеши паролей всех
  пользователей хранилища.

### Привязка `crs:bind` для чтения (2026-09-30, iljyxa/vscode-1c-repository-tools#14)

Вопрос из «Расхождения по `crs:bind`» закрыт пробами уровня тел (`example/crs/8.5.1/tcp/probe-*`,
скрипт `capture-read-probes.mjs` исходного проекта, сводка `read-probes-summary.json`) на `crserver` 8.5.1.1529.

- `DevDepot_devObjectsStatistic` без `crs:bind`, со случайным незарегистрированным `bindID`, с настоящим
  `bindID` Petrov на свежем соединении, от Reader без привязки и после `bind` новой привязки дают
  **побайтно одинаковые ответы**; захват Petrov виден во всех. Привязка для чтения не нужна.
- Сервер не хранит состояние сеанса: `authenticate` перед статистикой не требуется; неверный хеш без него —
  `auth-failed` (код 4).
- `DevDepot_bind` с незарегистрированным `bindID`: `existing=true` — отказ код 11 («Информационная база не
  связана с хранилищем конфигурации.»); `existing=false, force=false` — отказ код 10 (у пользователя уже
  есть другая база), привязка не появилась (`bindInfos` — 4 записи). `force=true` не пробовался: заменил
  бы привязку Petrov.
- `online`: ответ `bind` отдаёт `online=true`, но в следующей статистике у всех привязок `false` — устойчивой
  пометки `bind` не создаёт.
- Пустой `crserver`: после рукопожатия все пять методов — `depot-not-found`.
- Для `DevDepot_devDepotReport` (история) на момент #14 отдельной пробы не было. Проверено позже (2026-09-30,
  #21): история и `UserManager_depotUsers` отвечают без `crs:bind` и со случайным `bindID`, доступны `ReadOnly`
  — [06-crs-history.md](06-crs-history.md), раздел «Проверка `bind` для истории и пользователей».

Пробы снимаются телами, а не сырым потоком: в `bindInfos` ответов есть имя машины. Решение —
[repository-crs.md](../../repository-crs.md) (методы чтения: `bind` не нужен).

## Выводы

1. Метод и поля истории версий известны из crs-api для 8.3.x; на 8.5.1 метод другой —
   `DevDepot_devDepotReport`, см. [06-crs-history.md](06-crs-history.md).
2. Есть способ рукопожатия по версии и признак класса исключения — для конверта `crs:call`.
3. Имена пользователей берутся из статистики объектов, отдельного метода не нужно.
4. Всё это — сведения для 8.3.x по http. В тесты идут только артефакты, снятые на реальной платформе.
