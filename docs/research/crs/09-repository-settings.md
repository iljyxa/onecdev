# Параметры подключения к хранилищу: где их хранить

Дата: 2026-09-30, issue #95. Источники — исходники:

- vanessa-runner `ffab87a` (3.x, `main`);
- 1C: Platform Tools 0.9.10 (`ff26308`);
- v8vscedit `4c8d85f` (`~/projects/v8vscedit`, развитие прекращено).

Пути ниже даны относительно корня соответствующего репозитория.

Сейчас адрес и пользователь хранилища — настройки VS Code с областью `window`
(решение 12 исходного проекта). Заданные в настройках пользователя, они действуют во всех
окнах: другой проект подключается к чужому хранилищу. Его выгрузка при этом отбрасывается сверкой `rootId`,
но пользователь не видит почему. Описания хранилища в самом проекте нет.

## vanessa-runner

Набор опций `НаборОпцийХранилища` (`src/cli/НаборыОпций/НаборОпцийХранилища.os`):

| Опция | Смысл | Переменная окружения |
|---|---|---|
| `storage-name` | адрес хранилища конфигурации | `VRUNNER_STORAGE_NAME` |
| `storage-user` | пользователь хранилища | `VRUNNER_STORAGE_USER` |
| `storage-pwd` | пароль | `VRUNNER_STORAGE_PWD` |
| `storage-ver` | номер версии | `VRUNNER_STORAGE_VER` |

Набор подключают команды хранилища `repo create`, `bind`, `load`, `lock`, `unlock`, `commit`,
`create-user`, `copy-user`, `save-cf` (`src/cli/Repo_Подкоманды/`). Его же используют `run designer` и
`validate syntax-check`: если адрес задан, Конфигуратор запускается с подключением к хранилищу
(`ПараметрыХранилищаЕслиЗаданы`).

Запись в файле настроек:

- **2.x, `env.json`:** `"default": { "--storage-name": "…", "--storage-user": "…" }`. Опции с `--`
  допустимы и в секции конкретной команды (`loadrepo` и др.).
- **3.x, `autumn-properties.json`:** ключи без `--`. Общие опции лежат в секции `vrunner`
  (`"vrunner": { "storage-name": "…" }`), опции команд — во вложенных секциях иерархии команд
  (`examples/autumn-properties.json`: `vrunner.cf.compile.*`, `vrunner.test.xunit.*`).

Адрес — та же строка, что у `/ConfigurationRepositoryF` Конфигуратора: `tcp://…`, `http(s)://…`
или путь к каталогу файлового хранилища. Пароль берётся из файла или из переменной окружения. Своего
защищённого хранилища у vanessa-runner нет.

## 1C: Platform Tools

- **Команд хранилища нет:** в `src/` не встречаются ни `ConfigurationRepository`, ни `storage-*`.
- **Опции хранилища есть в редакторе профиля.** Кураторский слой `resources/schemas/vrunner-options.overrides.json`
  выделяет группу «Хранилище конфигурации» (`storage-name`, `storage-user`, `storage-pwd`, `storage-ver`).
  Каталоги опций `vrunner-options.v2.json` и `vrunner-options.v3.json` сгенерированы из схемы и
  исходников vanessa-runner. Значит, пользователь может завести адрес хранилища в профиле через UI
  Platform Tools, и это будет стандартная опция vanessa-runner.
- **`env.local.json` Platform Tools применяет только для** `ibconnection`, `db-user`, `db-pwd`,
  `v8version`, `additional` (`OVERRIDE_FIELD_BY_OPTION` в `src/shared/envProfiles.ts`). `storage-*` в
  этот список не входят. Читатель профиля исходного проекта (`core/platformTools/launchProfile.ts`, `localOptions`)
  берёт из `env.local.json` любую опцию.
- **Пароли** (`db-pwd`, `storage-pwd`) лежат в файлах профиля открытым текстом.
- **Что пишет редактор 0.9.7** (проверено на профилях, сгенерированных его кодом,
  `fixtures/platform-tools/0.9.7/profiles/storage/` исходного проекта): `env.local.json` — в обёртке `default`; опция без
  значения записывается пустой строкой (читатель считает её незаданной); пароль хранилища — открытым
  текстом.

## v8vscedit

Файл `src/infra/repository/RepositoryBindingStore.ts`:

- **Где лежит привязка.** В `env.json` в корне первой папки рабочей области (`extension.ts`:
  `folders[0]`). Ключи собственные, не vanessa-runner:
  - основная конфигурация — `default["--repo-path"]`, `default["--repo-user"]`;
  - расширения — `default.extension[<имя>] = { "repo-path", "repo-user" }`.
- **Цель привязки** — `RepositoryTarget`: каталог конфигурации, `cf | cfe`, имя расширения. У каждого
  расширения может быть своё хранилище.
- **Пароль** — в SecretStorage, ключ `v8vscedit.repository.<sha1(вид|каталог|расширение)>.password`
  (`ProjectSecretStorage.ts`, `RepositoryLockState.buildRepositoryScopeKey`). Пароль из прежних версий
  (`--repo-pwd` в `env.json`) при чтении переносится в SecretStorage и стирается из файла.
- **Запись.** Команда «Подключение к хранилищу» на корне дерева открывает форму «путь, пользователь,
  пароль» и запускает `/ConfigurationRepositoryBindCfg`. Привязка записывается в `env.json` только после
  успеха (`RepositoryCommands.ts`).
- **Чтение `env.json`** кэшируется по `mtime`. Пустой файл — допустимое состояние, повреждённый —
  понятная ошибка.

## Выводы для расширения

1. **Ключи — стандартные `storage-name` / `storage-user`.** Своих ключей, как у v8vscedit, не заводить.
   Тогда одна запись в профиле подходит нам, `vrunner repo …` и редактору Platform Tools.
2. **Порядок источников (принят):**
   1. профиль запуска Platform Tools: активный профиль и `env.json` / `autumn-properties.json` с
      перекрытиями `env.local.json`;
   2. настройки VS Code `1c-repository-tools.connection.*`;
   3. запрос при подключении.
3. **Запись (принята):** после успешной проверки подключения адрес, пришедший не из профиля,
   записывается в профиль с согласия пользователя:
   - `storage-name` — в базовый файл профиля: он общий для команды и лежит в git;
   - `storage-user` — в `env.local.json`: пользователь у каждого разработчика свой, файл в git не
     попадает.

   Файлы Platform Tools правятся бережно: без переформатирования и потери чужих ключей.
4. **Пользователь в `env.local.json`** — перекрытие, которое Platform Tools не применяет. Для него
   `storage-user` там не существует, но vrunner и мы читаем его одинаково. Для нас это приемлемо: сами
   хранилищем Platform Tools не пользуется.
5. **`storage-pwd` не используется.** Пароли — только в SecretStorage (запрет 4 в CLAUDE.md). Если
   пароль найден в профиле, это отмечается, как `hasDbPassword`. Ключ пароля остаётся «адрес +
   пользователь» (решение 12): он лучше ключа v8vscedit по каталогу, потому что одно хранилище в двух
   копиях проекта не требует ввода пароля дважды.
6. **Файловое хранилище** (путь к каталогу в `storage-name`) протоколом `crs` не обслуживается. Нужно
   понятное сообщение, а не ошибка разбора адреса.
7. **Отдельными задачами:**
   - хранилища расширений cfe (#97): у vanessa-runner стандартного ключа нет, у v8vscedit — собственная
     секция `extension`;
   - подключение на папку в рабочей области из нескольких папок (#98).

Реализация — #96. PR 1 (чтение профиля, правило файлового/серверного хранилища) выполнен, см. решение 12,
п. 10; PR 2 (цепочка источников «профиль → настройки → запрос», подтверждение адреса, UI) выполнен, см.
решение 12, п. 11; PR 3 (запись адреса и пользователя в профиль после успешного подключения, по явному
согласию) выполнен, см. решение 12, п. 12. Не покрыто настоящими фикстурами: неверный серверный адрес в
профиле и `https` (нужен сценарий в `fixtures/tools/platform-tools-storage-profiles.mjs`).

## Не проверено

- **Чтение опций команд в 3.x.** Читает ли vanessa-runner опции хранилища из секций команд
  (`vrunner.repo.load.storage-name`), если общей `vrunner.storage-name` нет. Порядок наследования опций
  autumn по исходникам не прослеживался.
- **Реакция редактора профиля Platform Tools на внешнюю правку.** Как он ведёт себя, если наш код пишет в файл
  профиля, пока тот открыт в его редакторе (перечитывание, перезапись). Известно по его коду: при добавлении
  опции он переписывает отступ предыдущей строки (пробелы → табуляция); запись расширения такую правку
  отвергает (решение 12, п. 12). Страхует сверка текста перед записью и проверка несохранённых правок.
- **`storage-user` в `env.local.json`.** Читает ли vanessa-runner это значение из локального файла.
