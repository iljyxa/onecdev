$ARGUMENTS

## Порядок

1. **Одна сессия — одна задача.** Если в этой сессии уже велась другая задача (есть история работы над
   другой веткой/issue), — остановись и попроси пользователя начать новую сессию: продолжение здесь
   оплачивает всю прежнюю историю на каждом ходу.
2. **ТЗ.** Для issue — `gh issue view <N> -R iljyxa/onecdev --json title,body,labels,comments`.
3. **Триаж** по разделу «Триаж» `docs/agentic-pipeline.md` (прочитай этот файл; `CLAUDE.md` уже в
   контексте): SOLO по умолчанию; FULL — новый тип/слот/тег/схема, центральные контракты, MCP-инструмент или
   канон путей, протокол webview↔расширение, новая подсистема; LARGE — FULL, не помещающийся в одну сессию.
   Назови трек одной строкой с причиной.
4. **Ветка** от `origin/main`: `git fetch origin && git switch -c <fix|feat|chore>/issue-<N>-<кратко> origin/main`.
5. **Трек:**
   - **SOLO:** рецепт из `docs/recipes/*.md` → точечная разведка (LSP, разделы docs) → все тесты → код →
     связанные тесты, compile, lint.
   - **FULL:** то же, но план — в plan mode (критерии приёмки, файлы по рецепту, сигнатуры, план тестов) с
     утверждением пользователя до кода; после гейта — агент `reviewer` (бриф: ТЗ, план, сводка гейта, база).
   - **LARGE:** агент `architect` пишет план в `docs/plans/` → агент `implementer` по одному этапу на запуск
     (бриф: путь к плану, номер этапа) → гейт → `reviewer` → `documenter`.
6. **QA-гейт:** `bash .claude/scripts/qa-gate.sh` в фоне. RED с очевидной причиной — чини сам; с
   неочевидной — агент `qa-e2e` по `out/qa-gate.log`. Затем гейт заново.
7. **Документация** — если изменился публичный контракт/поведение, обнови нужные `docs/` сам (LARGE —
   `documenter`).
8. **Коммиты** на ветке — на русском, без упоминаний Claude/ИИ. **PR** — по разделу «PR и ревью»
   `docs/agentic-pipeline.md`: push ветки, `gh pr create`, `gh pr checks --watch` в фоне, замечания —
   `bash .claude/scripts/pr-review-comments.sh <PR>`, правки до «нечего чинить».
9. **Merge** — только после явного подтверждения пользователя: `gh pr merge --merge --delete-branch` с
   темой «Влить <ветка>: … (#N)», затем `git switch main && git pull --ff-only`, удалить локальную ветку.
   После merge задача закончена — следующая задача в новой сессии.

Соблюдай «Гигиену контекста» из `docs/agentic-pipeline.md`. Итог пользователю: что сделано, сводка гейта,
итог ревью (CodeRabbit / `reviewer`), ссылка на PR.
