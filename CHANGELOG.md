## [0.6.0] — альфа

Первый выпуск onecdev — hard fork [v8vscedit](https://github.com/Macegor/v8vscedit) 0.5.0. Расширение
распространяется как VSIX из [GitHub Releases](https://github.com/iljyxa/onecdev/releases).

### Переход с v8vscedit

- Расширение переименовано: идентификатор `iljyxa.onecdev`, настройки `onecdev.*`, MCP-сервер и инструменты
  `onecdev_*`. Лицензия — GPL-3.0-only, авторство кода v8vscedit сохранено в `NOTICE`.
- Служебный каталог `.v8vscedit/` при первой активации переносится в `.onecdev/` (кэши, состояние захватов,
  снимки для слияния) и исключается из git собственным `.gitignore`.
- Адрес и пользователь хранилища хранятся в стандартных ключах vanessa-runner (`--storage-name`,
  `--storage-user`); старые `--repo-path`/`--repo-user` читаются и заменяются при следующем подключении.
- Что сделать вручную — раздел «Переход с v8vscedit» в README.

### Хранилище конфигурации

- Синхронизация файлов проекта с хранилищем: захват, освобождение, помещение и получение работают с файлами
  выгрузки, а не только с базой; захваченные объекты становятся редактируемыми, остальные — только для чтения.
- История хранилища и статусы захватов читаются по протоколу crs напрямую с сервера хранилища и
  синхронизируются с ним; при частичном отказе захвата записываются те объекты, что удалось захватить.
- Команды хранилища с узла формы, макета или вложенной подсистемы адресуют саму единицу; модуль формы и файлы
  корня конфигурации требуют захвата своего владельца.
- Понятные диалоги захвата, освобождения и получения; получение версии — отдельная команда; окно сравнения
  с хранилищем показывает стороны в едином порядке. Форма подключения и помещения не закрывается до успеха
  и проверяет поля до запуска конфигуратора.
- Конфигуратор запускается с параметрами подключённого хранилища; загрузка в привязанную к хранилищу базу
  не требует параметров хранилища; при отказе хранилища не выполняется бесполезная полная загрузка.
- В дереве — одна иконка захвата: закрытый замок у объектов, недоступных для редактирования.
- Временные файлы и каталоги операций с хранилищем подметаются, сбой удаления снимка не прерывает операцию.

### Метаданные и XML

- Генератор форм пишет формат выгрузки 2.21 по ruleset версии формата; заимствование формы с таблицей.
- Стандартные реквизиты: блоки по умолчаниям платформы, просмотр свойств без записи в XML, запись свойства
  с материализацией блока по шаблону ruleset.
- Заимствование в расширение сохраняет формат XML, регистрирует дочерние объекты в `ChildObjects` владельца
  и не портит синонимы с `$`-шаблонами.
- СКД: связи наборов, вариант настроек и порядок блоков — в формате платформы; разбор учитывает вложенность.
- Режим поддержки определяется для корневого `Ext/`, служебных XML и модулей подчинённых объектов; добавлен
  режим «снят с поддержки», запреты изменения объясняются причиной.
- Запись XML сохраняет BOM и переводы строк исходного файла построчно; повтор того же значения свойства —
  успех без изменений.

### MCP-сервер

- Импорт и обновление конфигурации без интерактивного выбора, явный исход команд `execute_command`.

### Проект и окружение

- Инициализация проекта не создаёт пустой каркас vanessa-bootstrap; `env.json` с BOM читается всеми
  читателями подключения и не переформатируется при сохранении настроек.
- `bsl-analyzer` перезапускается при появлении основной конфигурации, `.onecdev` исключается из анализа,
  сбой фонового LSP-запроса не показывает уведомлений.
- Замер фаз активации в канале «1С Редактор»; индекс рабочего дерева по `stat` вместо хеширования выгрузки.

### Пакет

- VSIX самодостаточен: `ssh2` и остальные зависимости вшиты в бандл, `node_modules` в пакет не попадает,
  тексты лицензий вшитых пакетов — в `dist/THIRD_PARTY_LICENSES.txt`.
- Локальные файлы рабочей копии разработчика (`env.json`, `.onecdev/` и т. п.) в VSIX не попадают.
- Исправлены уязвимости ReDoS из алертов CodeQL, `fast-xml-parser` обновлён до 4.5.7.
